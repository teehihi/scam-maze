# Implementation Plan

## Overview

Fix the startup and chapter loading screens that flash too fast to see. The plan follows the bugfix workflow: write a failing bug condition test, write preservation tests that pass on the unfixed code, apply the fix in the presentation layer (`fadeIn` option on `SceneTransition`, `useMinimumDisplayTime` hook and `shouldShowLoadingScreen` helper, holds of 1500 ms for chapter loading and 1200 ms for startup), then run all checks. `chapterLoader.ts` and `useChapterLoader.ts` stay unchanged.

  - **Property 2: Preservation** - Non-buggy runs, bypass actions and other behavior are unchanged
  - **IMPORTANT**: Follow the observation-first method. Run the UNFIXED code for runs where `isBugCondition` is false, record the observed behavior, then write tests that assert it

    - Unmount: unmounting during loading aborts downloads, leaves `vi.getTimerCount()` at 0, calls no handler and logs no `console.error`
    - Reduced motion: transitions use `0ms` and show and hide are instant
    - Default fade-in: `SceneTransition` rendered without a `fadeIn` prop is `hidden` on the first render, becomes `visible` after the animation frame, and calls `onHidden` exactly once, even when `visible` toggles more than once
